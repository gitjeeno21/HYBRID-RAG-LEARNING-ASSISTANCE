## Decision: not adopted

Under the pre-registered rule (no loss on dev, gain on held-out), **hybrid_s2b is rejected**:

- dev: hit@5 tied 42/50 (3 better, 3 worse), nDCG@5 −0.003;
- held-out: hit@5 43 → 42 (0 better, 1 worse); every-quote-in-prompt 41 → 38 of 47.

**What it did confirm:** the embedding-window diagnosis was right. On *dense search alone*, small-to-big lifts dev hit@5 from 33 to 38 (66% → 76%) and held-out from 40 to 42, with nDCG up on both sets. Text past MiniLM's 256-token window really was invisible to dense search.

**Why it does not carry over to hybrid:** BM25 has no window and already retrieves the tail of a chunk that dense search cannot see, which is exactly why hybrid beat dense in the first place. Small-to-big changes *which* parents dense search ranks highly, so the two lists agree less often, and RRF, which rewards agreement, demotes some passages both used to find. It also doubles dense latency (1,376 child vectors vs 368; ~29 ms vs ~14 ms).

Not pursued further: tuning child size or fusion weights against these same question sets would be fitting to the test set. A different embedding model with a longer window (bge-small, Phase 3) was likewise rejected.
